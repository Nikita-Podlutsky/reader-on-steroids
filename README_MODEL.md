# Модель ранжирования Kotodex

Документ описывает архитектуру `UniversalScorer`, процесс подготовки данных и обучения.

---

## Идея

Стандартный bi-encoder (два независимых энкодера, скалярное произведение) не учитывает контекст запроса при кодировании документа. Документ кодируется один раз и одинаково для любого запроса.

Здесь сделано иначе: **документ кодируется с учётом запроса**. DocumentEncoder на вход получает не только предложения статьи, но и вектор запроса — и через механизм внимания взвешивает предложения по их релевантности именно этому запросу. Для одной и той же статьи по запросу "gradient descent convergence" и "transformer attention mechanisms" модель выдаст разные представления, и это правильно.

---

## Архитектура

### QueryEncoderBGE

Основа — `BAAI/bge-small-en-v1.5` (BERT-like, 384-мерные эмбеддинги), обёрнутый в **QLoRA** (4-bit NF4 квантизация).

```
Запрос (текст)
    → Tokenizer (max 512 токенов)
    → BGE-small [заморожен, 4-bit] + QLoRA адаптеры [r=64, α=128]
    → Mean pooling по токенам
    → Projection [384 → 192 → 768]
    → Вектор запроса q ∈ ℝ^768
```

Параметры LoRA охватывают все основные слои трансформера: `query`, `key`, `value`, `attention.output.dense`, `intermediate.dense`, `output.dense`. Это даёт модели возможность переориентироваться под задачу ранжирования, не теряя предобученных знаний о языке.

Выходная размерность специально совпадает с размерностью Longformer (768), чтобы сравнение было в едином пространстве.

---

### DocumentEncoder

Основа — `allenai/longformer-base-4096` с **обычной LoRA** (16-bit, r=32, α=64).

Longformer выбран потому, что статьи — длинные документы. BGE-small на 512 токенах срезает большую часть текста, Longformer держит до 4096. В нашем случае входом служат не токены, а **заранее посчитанные сентенс-эмбеддинги предложений** (384-мерные, от BGE-small) — это позволяет обойти ограничение по длине совсем: статья из 200 предложений входит целиком.

```
Документ (список предложений S₁...Sₙ)
    → BGE-small → матрица эмбеддингов [N × 384]   (предпосчитано)
    → sentence_projection [384 → 768]
    → Longformer [заморожен] + LoRA [r=32]         (global attention на первом токене)
    → transformer_output [N × 768]

Запрос q ∈ ℝ^768
    → query_projection [768 → 768]
    → expand → [N × 768]

[transformer_output || query_projected] → attention [1536 → 1] → softmax
    → weighted sum по предложениям
    → LayerNorm
    → Вектор документа d ∈ ℝ^768
```

Механизм внимания (`attention`) — простая линейная голова, которая конкатенирует представление каждого предложения с вектором запроса и выдаёт скаляр важности. Предложения, нерелевантные запросу, получают близкий к нулю вес.

Global attention Longformer'а установлен на первом предложении — это даёт модели "опорную точку" для построения контекста всего документа.

---

### UniversalScorer

Обёртка над двумя энкодерами. На инференсе используется только для получения пар (q, d) — скор это косинусное сходство нормализованных векторов.

При обучении прогоняет три документа через DocumentEncoder (anchor, positive, negative) с одним и тем же вектором запроса.

```
Лосс: TripletMarginLoss(margin=0.2)
    = max(0, d(q, anchor) - d(q, positive) + margin)
```

Цель: positive должен быть ближе к запросу, чем anchor, как минимум на 0.2.

## Данные

### Источник

ArXiv metadata snapshot (~2M статей). Из него отбирается сбалансированная выборка по категориям (2020+):

| Категория | Кол-во |
|-----------|--------|
| cs.CL     | 500    |
| cs.CV     | 400    |
| cs.LG     | 100    |
| quant-ph  | 100    |
| hep-ph    | 100    |

После отбора скачиваются PDF, из них извлекается полный текст через PyMuPDF.

### Генерация запросов

Каждая статья прогоняется через Ollama (`gemma3:latest`). Модель по заголовку и абстракту генерирует 3 синтетических поисковых запроса и помечает модальность и задачу статьи. Запросы намеренно короткие и сформулированы как пользовательские, а не как названия статей — это важно, чтобы обучить модель на реальном семантическом разрыве между запросом и документом.

### Триплеты

Триплет: `(query, anchor, positive, negative)`.

- **anchor** — статья, семантически близкая к positive (по косинусному сходству BGE-эмбеддингов)
- **positive** — статья, из которой взят запрос
- **negative** — статья из пересекающейся категории с anchor, но далёкая семантически

Жёсткие негативы (hard negatives) нужны чтобы модель не переобучалась на тривиальных примерах. Поиск делается за 500 попыток: из случайных кандидатов берётся тот, у которого наименьшее косинусное сходство с anchor, но та же категория. Это даёт "тематически похожий, но семантически далёкий" негатив — именно тот случай, где простые модели ошибаются.

Итого: 20 000 триплетов.

### Предобработка эмбеддингов

Перед обучением для каждого уникального документа считаются эмбеддинги всех предложений и сохраняются в `.pt` файл. Это делает датасет независимым от BGE-small в runtime — при обучении не нужно заново кодировать предложения.

Файлы хранятся в хэш-структуре: `embeddings_pt/20/01/200100116.pt` — это избегает проблем с файловыми системами при большом количестве файлов.

---

### Online Hard Negative Mining

`HierarchicalTripletDataset2` реализует динамический поиск негативов прямо в `__getitem__` без предпосчёта. Для каждого батча:

1. Берётся mean-вектор anchor (1×384)
2. Из пула 10k документов (`doc_pool.pt`) случайно выбирается 5000 кандидатов
3. Считается косинусное сходство, берётся тот у кого оно минимально
4. Загружается его `.pt` файл как negative

Это дороже статичных триплетов, но даёт более информативный градиент на каждом шаге.

## Обучение

```
Модель:    UniversalScorer (BGE-small QLoRA + Longformer LoRA)
Лосс:      TripletMarginLoss (margin=0.2)
Оптимизатор: AdamW (lr=2e-5, weight_decay=0.01)
Scheduler: LinearWarmup (100 шагов) + LinearDecay
Precision: bfloat16 (AMP)
Batch:     4 (effective 8 с gradient accumulation × 2)
Epochs:    10
Gradient clipping: max_norm=1.0
```

Gradient checkpointing включён для Longformer — без него модель не помещается в память при обучении.

### Чекпоинты

Система чекпоинтов сохраняет LoRA-адаптеры отдельно от основных весов:

```
best_model.pt/
├── query_encoder_lora/     ← PEFT адаптеры QueryEncoder
│   ├── adapter_config.json
│   └── adapter_model.safetensors
├── document_encoder_lora/  ← PEFT адаптеры DocumentEncoder
│   ├── adapter_config.json
│   └── adapter_model.safetensors
├── model_state.pt          ← projection, attention, layernorm
└── training_state.pt       ← optimizer, scheduler, scaler, epoch/step
```

Сохранение атомарное: сначала пишется во временную директорию, потом переименовывается. Это исключает ситуацию когда упавший процесс оставляет полупустой чекпоинт. Автосохранение каждые 50 шагов (`autosave.pt`).

## Бенчмарк

`benchmark.py` сравнивает три метода ранжирования на одних данных.

**Методы:**

| Метод | Описание |
|-------|----------|
| Custom Model | UniversalScorer с полным forward pass |
| Baseline Mean | Mean pooling предложений → косинус с запросом |
| Baseline MaxSim | MaxSim (ColBERT-style) по проекциям предложений |

**Метрики** (K = 1, 3, 5, 10):

- Hit@K, NDCG@K, Precision@K, Recall@K
- MRR, MAP
- Latency: mean, P50, P95, P99

**Протокол:** 200 запросов, для каждого — 1 релевантный документ + 99 случайных негативов из батча. Метки: `y_true[0] = 1`, остальные 0. Порядок: релевантный всегда первый кандидат (честно — модель не знает об этом).

Дополнительно анализируется качество в зависимости от длины документа: Short (<10 предложений), Medium (10–30), Long (30–50), Very Long (50+). Это важно потому что Longformer должен работать лучше именно на длинных документах — если это не так, значит что-то пошло не так при обучении.

Результаты сохраняются в `benchmark_results/results_YYYYMMDD_HHMMSS.json`.

## Воспроизведение

```bash
# 1. Подготовка данных (несколько часов, нужен Ollama)
python data_prepair.py

# 2. Предпосчёт пула для hard negative mining
python precompute_docs.py

# 3. Валидация метаданных (убирает битые записи)
python validate_metadata.py

# 4. Обучение
python train.py

# 5. Бенчмарк
python benchmark.py
```

Для возобновления обучения с чекпоинта: `RESUME_TRAINING = True` в `config.py`.
